# US-01: Public catalog and asset search (5 points)

As a Student, I want to browse the equipment catalog by type, location and status, so that I can see
what is available before I walk to the desk.

**Page:** `/catalog/` (open to everyone, no sign-in).
**Code:** `inventory/views/catalog.py`, `inventory/forms.py`, `inventory/templates/inventory/catalog.html`,
`inventory/models.py`.

## What it does

- Lists every item that is not retired: asset tag, type, location, status.
- Filter boxes for asset tag, type, location and status. Blank boxes are ignored; type and location match
  part of a word without caring about case.
- Available items get a green badge. Checked Out and Repair items stay in the list with a grey or amber
  "Unavailable" badge.
- The page only reads four columns from the database, so borrower details cannot appear.
- `/checkout/` is Staff-only: signed-out visitors go to sign-in and Students get 403.

## Demo, step by step

**Before you start** (see `docs/SETUP.md` for first-time setup). Make sure Postgres is running, then reset the demo data:

```bash
cd equipment-checkout
source .venv/bin/activate
export DB_PASSWORD=your-password
python manage.py flush --no-input
python manage.py seed_demo
python manage.py runserver
```

Open http://127.0.0.1:8000/. Every demo login uses the password `demo-pass-123`. Use a normal window and a
private window to be signed in as two people at once.

**How to sign in.** Click **Sign in** at the top right of any page, or go to http://127.0.0.1:8000/accounts/login/.
After `seed_demo`, these three logins work straight away (password `demo-pass-123` for all):

| Username | Role | What they see |
| --- | --- | --- |
| `admin1` | Admin | Everything: Inventory, Roster, Staff, plus all the desk pages |
| `staff1` | Staff | Checkout, Return, Overdue, Event log |
| `zquin001` | Student | My loans |

The other students (`mrive002`, `jchen003`, ...) have no password until they activate. Go to
http://127.0.0.1:8000/accounts/activate/ (also linked from the sign-in page), type the username and that student's
activation code (printed in the terminal by `seed_demo`), then choose a password. To switch users, click **Sign out**
at the top right, or use the private window.

If sign-in fails, check that you ran `seed_demo` after the last `flush` (flush deletes every account), that
the server is still running at `127.0.0.1:8000`, and that the password is all lowercase.

**Seeded state:** CHG-002, CALC-001 and LAP-001 are Checked Out. HDMI-001 and HEAD-002 are in Repair. CAM-001 is retired.

1. While signed out, open **Catalog** (`/catalog/`). No sign-in is needed. Point out that each row shows only asset tag,
   type, location and status. *(AC 1)*
2. Type `charger` in **Type** and click Filter. All three chargers appear, so the match is partial and ignores case.
   Clear the box, choose **Repair** under status, click Filter,, and only HDMI-001 and HEAD-002 are left. *(AC 2)*
3. Clear the filters. CHG-002 has a grey **Unavailable: Checked Out** badge and HDMI-001 has an amber **Unavailable: Repair** one. Both are still listed.
   CAM-001 is retired, so it does not appear. *(AC 3)*
4. CHG-002 is on loan to Zelda Quintero (`zquin001`, `6000001`). Use Cmd+F to search the page for `Zelda`,
   `zquin001` and `6000001`. Nothing is found. *(AC 4)*
5. While signed out, go to `/checkout/` and you are sent to sign-in. Sign in as `zquin001` and open `/checkout/` again.
   The page returns **403 Forbidden**. *(AC 5)*
6. Sign out, sign in as `staff1`, open **Return**, and return `CHG-002` without the damaged box ticked. Refresh the catalog:
   CHG-002 now shows a green **Available** badge. *(AC 6)*

**Tests:** `pytest inventory/tests/test_catalog.py inventory/tests/test_access.py -v`

## Acceptance criteria and the tests that prove them

| # | Acceptance criterion | Test |
| --- | --- | --- |
| 1 | Each row shows asset tag, type, location and status | `test_catalog.py::test_catalog_row_shows_four_fields` |
| 2 | Status is one of Available, Checked Out or Repair | `test_models.py::test_status_limited_to_three_choices`, `test_database_refuses_unknown_status` |
| 3 | Checked Out and Repair items are visible but badged unavailable | `test_catalog.py::test_unavailable_items_visible_and_badged` |
| 4 | Rows never show borrower name, Panther ID, email or phone | `test_catalog.py::test_catalog_hides_borrower_fields` |
| 5 | A Student cannot open the checkout form | `test_access.py::test_student_gets_403_on_checkout` |
| 6 | After a checkout or return is saved, the catalog shows the new status | `test_catalog.py::test_catalog_reflects_status_change` |

The privacy test now checks out an item first, so the borrower really exists, and looks for the
username, name, mock Panther ID and phone. The status-change test uses the real checkout and return.
