# US-01: Public catalog and asset search (5 points)

As a Student, I want to browse the equipment catalog by type, location and status, so that I can see
what is available before I walk to the desk.

**Page:** `/catalog/` (open to everyone, no sign-in).
**Code:** `inventory/views/catalog.py`, `inventory/forms.py`, `inventory/templates/inventory/catalog.html`,
`inventory/models.py`.

## What it does

- Lists every item that is not retired: asset tag, type, location, status.
- Filter boxes for asset tag, type, location and status. Blank boxes are ignored; type and location match
  part of a word without caring about case.
- Available items get a green badge. Checked Out and Repair items stay in the list with a grey or amber
  "Unavailable" badge.
- The page only reads four columns from the database, so borrower details cannot appear.
- `/checkout/` is a Staff-only placeholder: signed-out visitors go to sign-in and Students get 403.

## Acceptance criteria and the tests that prove them

| # | Acceptance criterion | Test |
| --- | --- | --- |
| 1 | Each row shows asset tag, type, location and status | `test_catalog.py::test_catalog_row_shows_four_fields` |
| 2 | Status is one of Available, Checked Out or Repair | `test_models.py::test_status_limited_to_three_choices`, `test_database_refuses_unknown_status` |
| 3 | Checked Out and Repair items are visible but badged unavailable | `test_catalog.py::test_unavailable_items_visible_and_badged` |
| 4 | Rows never show borrower name, Panther ID, email or phone | `test_catalog.py::test_catalog_hides_borrower_fields` |
| 5 | A Student cannot open the checkout form | `test_access.py::test_student_gets_403_on_checkout` |
| 6 | After a checkout or return is saved, the catalog shows the new status | `test_catalog.py::test_catalog_reflects_status_change` |
