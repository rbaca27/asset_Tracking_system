# US-02: Semester roster import (5 points)

As an Admin, I want to import the department's semester enrollment roster as a CSV file, so that every
student enrolled in a department course has a local account and students who are no longer enrolled
cannot sign in.

**Page:** `/accounts/roster/` (Admin only).
**Code:** `inventory/views/roster_import.py`, `AccountService.import_roster` in `inventory/services.py`,
`Profile` and `RosterImport` in `inventory/models.py`, `templates/inventory/roster_import.html`.
**Sample file:** `inventory/fixtures/mock_roster.csv`, columns `panther_id, username, display_name, email, phone`.

## What it does

- Validates every row before saving anything. Row numbers match the CSV line (header = row 1).
- New Panther ID: creates a Student account with no usable password and a one-time activation code.
- Known Panther ID: updates email, name, phone and term; reactivates the account if needed.
- Students missing from the file are deactivated, never deleted. Staff and Admin accounts are never deactivated.
- Shows created / updated / deactivated counts and the activation codes, once. Codes are stored only as hashes.

## Demo, step by step

**Before you start** (see `docs/SETUP.md` for first-time setup). Make sure Postgres is running, then reset the demo data:

```bash
cd equipment-checkout
source .venv/bin/activate
export DB_PASSWORD=your-password
python manage.py flush --no-input
python manage.py seed_demo
python manage.py runserver
```

Open http://127.0.0.1:8000/. Every demo login uses the password `demo-pass-123`. Use a normal window and a
private window to be signed in as two people at once.

**How to sign in.** Click **Sign in** at the top right of any page, or go to http://127.0.0.1:8000/accounts/login/.
After `seed_demo`, these three logins work straight away (password `demo-pass-123` for all):

| Username | Role | What they see |
| --- | --- | --- |
| `admin1` | Admin | Everything: Inventory, Roster, Staff, plus all the desk pages |
| `staff1` | Staff | Checkout, Return, Overdue, Event log |
| `zquin001` | Student | My loans |

The other students (`mrive002`, `jchen003`, ...) have no password until they activate. Go to
http://127.0.0.1:8000/accounts/activate/ (also linked from the sign-in page), type the username and that student's
activation code (printed in the terminal by `seed_demo`), then choose a password. To switch users, click **Sign out**
at the top right, or use the private window.

If sign-in fails, check that you ran `seed_demo` after the last `flush` (flush deletes every account), that
the server is still running at `127.0.0.1:8000`, and that the password is all lowercase.

**Prepare a "new semester" file.** In a second terminal tab inside the project folder, run these two lines. They drop
Kayla (`kjohn006`) and add Luis (`lgarc007`):

```bash
grep -v kjohn006 inventory/fixtures/mock_roster.csv > ~/Desktop/spring_roster.csv
echo "6000007,lgarc007,Luis Garcia,lgarc007@mock.fiu.edu,305-555-0107" >> ~/Desktop/spring_roster.csv
```

1. Sign in as `staff1` and go to `/accounts/roster/`. The page returns **403**. Sign out, sign in as `admin1`, and click
   **Roster**. The page opens. *(AC 1)*
2. Enter `Spring 2027` as the term, choose `~/Desktop/spring_roster.csv`, and click **Import**. The result reads
   **1 created, 5 updated, 1 deactivated**. *(AC 2, 4, 6, 7)*
3. Luis's one-time activation code is shown once. Copy it now because it is stored only as a hash. Luis has no
   usable password yet, and the US-08 demo uses this code. *(AC 3)*
4. Import the same file again. This time it reports **0 created, 6 updated**: accounts are matched by Panther ID, so no
   duplicates are made. *(AC 4)*
5. Open `spring_roster.csv` in a text editor and change one email to `not-an-email`. Optionally, blank out
   someone's username as well. Import it. The **whole file is rejected**, each error names its row number
   (the header is row 1), and the counts are unchanged. *(AC 5)*
6. In the private window, try signing in as `kjohn006`. You get the generic sign-in error. To show the account was
   only deactivated, not deleted, run this in the second terminal tab:
   `python manage.py shell -c "from django.contrib.auth.models import User; print(User.objects.filter(username__in=['kjohn006','staff1','admin1']).values_list('username','is_active'))"`.
   It prints `kjohn006` with `False`, so the row and its history are still there. `staff1` and `admin1` were not in the
   file but stay `True`. *(AC 6)*

**Tests:** `pytest inventory/tests/test_roster_import.py -v`
