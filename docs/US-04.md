# US-04: Equipment return and optional damage note (5 points)

As a Staff member, I want to process a return and, when needed, add a damage note, so that a damaged
item leaves circulation.

**Page:** `/return/` (Staff and Admin).
**Code:** `inventory/views/return_item.py`, `LoanService.return_item` in `inventory/services.py`,
`templates/inventory/return.html`.

## What it does

- The asset tag alone finds the active loan; no borrower lookup is needed.
- Not damaged: closes the loan, sets Available, logs RETURN.
- Damaged: a non-empty note is required (form, service and a database check constraint); closes the loan,
  sets Repair, logs RETURN and DAMAGE_TO_REPAIR. Only an Admin can clear Repair (US-07).

## Demo, step by step

**Before you start** (see `docs/SETUP.md` for first-time setup). Make sure Postgres is running, then reset the demo data:

```bash
cd equipment-checkout
source .venv/bin/activate
export DB_PASSWORD=your-password
python manage.py flush --no-input
python manage.py seed_demo
python manage.py runserver
```

Open http://127.0.0.1:8000/. Every demo login uses the password `demo-pass-123`. Use a normal window and a
private window to be signed in as two people at once.

**How to sign in.** Click **Sign in** at the top right of any page, or go to http://127.0.0.1:8000/accounts/login/.
After `seed_demo`, these three logins work straight away (password `demo-pass-123` for all):

| Username | Role | What they see |
| --- | --- | --- |
| `admin1` | Admin | Everything: Inventory, Roster, Staff, plus all the desk pages |
| `staff1` | Staff | Checkout, Return, Overdue, Event log |
| `zquin001` | Student | My loans |

The other students (`mrive002`, `jchen003`, ...) have no password until they activate. Go to
http://127.0.0.1:8000/accounts/activate/ (also linked from the sign-in page), type the username and that student's
activation code (printed in the terminal by `seed_demo`), then choose a password. To switch users, click **Sign out**
at the top right, or use the private window.

If sign-in fails, check that you ran `seed_demo` after the last `flush` (flush deletes every account), that
the server is still running at `127.0.0.1:8000`, and that the password is all lowercase.

**Seeded state:** CHG-002 is on loan to `zquin001` and CALC-001 is on loan to `mrive002`.

1. While signed out, go to `/return/` and you are sent to sign-in. As `zquin001`, the page returns **403**. *(AC 1)*
2. Sign in as `staff1` and click **Return**. Type `CALC-001`, leave **Damaged** unticked, and click **Process return**.
   The return is accepted with no note, and the catalog shows CALC-001 as **Available**. *(AC 2)*
3. Type `CHG-002`, tick **Damaged**, leave the note empty, and submit. The page says **"A damage note is required."**
   and nothing changes. *(AC 3)*
4. Add the note `frayed cable` and submit again. The return is accepted, and the catalog shows CHG-002 with an amber
   **Repair** badge. *(AC 3)*
5. Click **Checkout** and try `zquin001` + `CHG-002`. It is **blocked** because the item is in Repair. Only an Admin
   can clear Repair (see the US-07 demo). *(AC 4)*
6. Open **Event log**. You see **Return** for CALC-001, then **Return** and **Damaged, moved to Repair** for CHG-002,
   with the note "frayed cable". *(AC 5)*

**Tests:** `pytest inventory/tests/test_return.py -v`
