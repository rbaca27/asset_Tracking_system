# US-09: Staff accounts and role assignment (1 point)

As an Admin, I want to create Staff accounts and add or remove the Staff role, so that only current desk
workers can record loans.

**Page:** `/accounts/staff/` (Admin only).
**Code:** `inventory/views/staff_roles.py`, `AccountService.create_staff` and `set_staff_role` in
`inventory/services.py`, `templates/inventory/staff_roles.html`.

## What it does

- Create a new desk account in the Staff group, or add the Staff role to an existing account (for example a
  student worker, who then holds both Student and Staff).
- Remove the Staff role with one button. Access is checked on every request, so removal takes effect at once.
- Staff accounts never get `is_staff`, so they cannot enter the Django admin site (D-05).

## Demo, step by step

**Before you start** (see `docs/SETUP.md` for first-time setup). Make sure Postgres is running, then reset the demo data:

```bash
cd equipment-checkout
source .venv/bin/activate
export DB_PASSWORD=your-password
python manage.py flush --no-input
python manage.py seed_demo
python manage.py runserver
```

Open http://127.0.0.1:8000/. Every demo login uses the password `demo-pass-123`. Use a normal window and a
private window to be signed in as two people at once.

**How to sign in.** Click **Sign in** at the top right of any page, or go to http://127.0.0.1:8000/accounts/login/.
After `seed_demo`, these three logins work straight away (password `demo-pass-123` for all):

| Username | Role | What they see |
| --- | --- | --- |
| `admin1` | Admin | Everything: Inventory, Roster, Staff, plus all the desk pages |
| `staff1` | Staff | Checkout, Return, Overdue, Event log |
| `zquin001` | Student | My loans |

The other students (`mrive002`, `jchen003`, ...) have no password until they activate. Go to
http://127.0.0.1:8000/accounts/activate/ (also linked from the sign-in page), type the username and that student's
activation code (printed in the terminal by `seed_demo`), then choose a password. To switch users, click **Sign out**
at the top right, or use the private window.

If sign-in fails, check that you ran `seed_demo` after the last `flush` (flush deletes every account), that
the server is still running at `127.0.0.1:8000`, and that the password is all lowercase.

1. Sign in as `staff1` and go to `/accounts/staff/`. The page returns **403**. Only Admins manage roles. Sign out. *(AC 1)*
2. Sign in as `admin1` and click **Staff**. Under **Create a Staff account**, enter `desk2` with the password
   `demo-pass-123` and click **Create**. `desk2` appears under **Current Staff**. Creating `desk2` again is
   refused. *(AC 1)*
3. In the private window, sign in as `desk2`. **Checkout**, **Return**, **Overdue** and **Event log** all open.
   **Inventory**, **Roster** and **Staff** are not shown, and `/accounts/staff/` returns **403**. *(AC 2)*
4. Student worker: in the main window as `admin1`, use **Add the Staff role to an existing account** with `zquin001`.
   Zelda now holds **both** roles. *(AC 4)*
5. In the private window, sign out and sign in as `zquin001`. The navbar shows **My loans** *and* the desk pages.
   Open **Checkout**. *(AC 2, 4)*
6. In the main window, click **Remove Staff role** next to `zquin001`. In the private window, refresh Checkout.
   It returns **403** straight away, with no need to sign out. **My loans** still works. *(AC 3)*

**Tests:** `pytest inventory/tests/test_staff_roles.py inventory/tests/test_access.py -v`

## Acceptance criteria and the tests that prove them

| # | Acceptance criterion | Test (`tests/test_staff_roles.py`) |
| --- | --- | --- |
| 1 | Only an Admin can create a Staff account or change groups | `test_only_admin_creates_staff_or_changes_groups`, `test_admin_creates_staff_account`, `test_duplicate_username_refused` |
| 2 | A user added to Staff can open checkout, return and overdue | `test_added_staff_opens_desk_pages` |
| 3 | A user removed from Staff gets 403 on those pages | `test_removed_staff_gets_403` |
| 4 | A student worker can be in both Student and Staff | `test_student_worker_holds_both_groups` |

Access to every Staff and Admin page by every role is also checked in `tests/test_access.py`.
