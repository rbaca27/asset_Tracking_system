# US-03: Walk-up equipment checkout (8 points)

As a Staff member, I want to record a loan by typing a local student account or that account's mock
Panther ID and a typed asset tag, so that custody and a policy-based due time are stored.

**Page:** `/checkout/` (Staff and Admin).
**Code:** `inventory/views/checkout.py`, `LoanService.resolve_borrower` and `LoanService.checkout` in
`inventory/services.py`, `Loan` in `inventory/models.py`, `templates/inventory/checkout.html`.

## What it does

- One typed borrower field: username first, then mock Panther ID (D-12). No student list is rendered.
- Locks the asset row (`select_for_update`), then blocks unknown, retired, Checked Out and Repair items.
- Writes the loan (due = now + `asset.loan_duration`), sets Checked Out, and logs CHECKOUT in one transaction.
- A partial unique constraint allows only one active loan per asset, as a database backstop (D-04).

## Demo, step by step

**Before you start** (see `docs/SETUP.md` for first-time setup). Make sure Postgres is running, then reset the demo data:

```bash
cd equipment-checkout
source .venv/bin/activate
export DB_PASSWORD=your-password
python manage.py flush --no-input
python manage.py seed_demo
python manage.py runserver
```

Open http://127.0.0.1:8000/. Every demo login uses the password `demo-pass-123`. Use a normal window and a
private window to be signed in as two people at once.

**How to sign in.** Click **Sign in** at the top right of any page, or go to http://127.0.0.1:8000/accounts/login/.
After `seed_demo`, these three logins work straight away (password `demo-pass-123` for all):

| Username | Role | What they see |
| --- | --- | --- |
| `admin1` | Admin | Everything: Inventory, Roster, Staff, plus all the desk pages |
| `staff1` | Staff | Checkout, Return, Overdue, Event log |
| `zquin001` | Student | My loans |

The other students (`mrive002`, `jchen003`, ...) have no password until they activate. Go to
http://127.0.0.1:8000/accounts/activate/ (also linked from the sign-in page), type the username and that student's
activation code (printed in the terminal by `seed_demo`), then choose a password. To switch users, click **Sign out**
at the top right, or use the private window.

If sign-in fails, check that you ran `seed_demo` after the last `flush` (flush deletes every account), that
the server is still running at `127.0.0.1:8000`, and that the password is all lowercase.

1. While signed out, go to `/checkout/`. You are sent to sign-in. Sign in as `zquin001` and go to `/checkout/` again.
   The page returns **403**. Sign out. *(AC 1)*
2. Sign in as `staff1` and click **Checkout**. The form has only two typed boxes and shows no list of students. *(AC 2)*
3. Enter borrower `zquin001` and asset `CHG-001`, then submit. The confirmation shows the borrower, the item, and a
   **due time 4 hours from now**, which is CHG-001's loan-policy duration. *(AC 2, 5)*
4. Enter borrower `6000001` (Zelda's mock Panther ID) and asset `ADPT-001`. This also succeeds, so one student can hold
   several different items. *(AC 2, 4)*
5. Try these, one at a time:
   - `zquin001` + `CHG-001`: blocked, already Checked Out. *(AC 3, 4)*
   - `zquin001` + `HDMI-001`: blocked, in Repair. *(AC 3)*
   - `zquin001` + `CAM-001`: blocked, retired. `nobody99` + `CHG-003`: the borrower is not found. *(AC 2, 3)*
6. Open **Catalog**. CHG-001 and ADPT-001 now show **Checked Out**. *(AC 6)*
7. Open **Event log**. The two new **Checkout** rows are at the top, with `staff1` as the actor. *(AC 7)*

**Tests:** `pytest inventory/tests/test_checkout.py -v`
