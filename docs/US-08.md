# US-08: Student account activation and sign-in (2 points)

As a Student, I want to activate my account once and then sign in with my username and password, so that
I can see my own loans.

**Pages:** `/accounts/activate/` (first visit), `/accounts/login/` and sign-out (Django's own views).
**Code:** `inventory/views/activate.py`, `AccountService.activate` in `inventory/services.py`,
`templates/registration/activate.html`, `templates/registration/login.html`.

## What it does

- The student types username, one-time code and a new password (Django's password rules apply).
- A wrong, used or expired code, an unknown username, or a deactivated account all show one generic message.
- The code is single-use: it is cleared on success. Codes last `ACTIVATION_CODE_LIFETIME` (30 days, `config/settings.py`).
- Later visits use Django's LoginView, which refuses deactivated accounts with the same generic error.

## Acceptance criteria and the tests that prove them

| # | Acceptance criterion | Test (`tests/test_activation.py`) |
| --- | --- | --- |
| 1 | A student activates with username and valid code, then picks a password | `test_activate_with_valid_code`, `test_weak_password_rejected_and_code_still_usable` |
| 2 | A wrong, used or expired code is rejected generically | `test_bad_code_rejected_generically` |
| 3 | The stored password is a hash | `test_password_stored_as_hash` |
| 4 | Sign-in uses a local username and password | `test_sign_in_is_local_username_and_password` |
| 5 | A wrong password does not reveal whether the username exists | `test_wrong_password_generic_error` |
| 6 | A deactivated account cannot sign in | `test_deactivated_account_cannot_sign_in` |
| 7 | A signed-in student can sign out | `test_signed_in_student_can_sign_out` |
