# US-08: Student account activation and sign-in (2 points)

As a Student, I want to activate my account once and then sign in with my username and password, so that
I can see my own loans.

**Pages:** `/accounts/activate/` (first visit), `/accounts/login/` and sign-out (Django's own views).
**Code:** `inventory/views/activate.py`, `AccountService.activate` in `inventory/services.py`,
`templates/registration/activate.html`, `templates/registration/login.html`.

## What it does

- The student types username, one-time code and a new password (Django's password rules apply).
- A wrong, used or expired code, an unknown username, or a deactivated account all show one generic message.
- The code is single-use: it is cleared on success. Codes last `ACTIVATION_CODE_LIFETIME` (30 days, `config/settings.py`).
- Later visits use Django's LoginView, which refuses deactivated accounts with the same generic error.

## Demo, step by step

**Before you start** (see `docs/SETUP.md` for first-time setup). Make sure Postgres is running, then reset the demo data:

```bash
cd equipment-checkout
source .venv/bin/activate
export DB_PASSWORD=your-password
python manage.py flush --no-input
python manage.py seed_demo
python manage.py runserver
```

Open http://127.0.0.1:8000/. Every demo login uses the password `demo-pass-123`. Use a normal window and a
private window to be signed in as two people at once.

**How to sign in.** Click **Sign in** at the top right of any page, or go to http://127.0.0.1:8000/accounts/login/.
After `seed_demo`, these three logins work straight away (password `demo-pass-123` for all):

| Username | Role | What they see |
| --- | --- | --- |
| `admin1` | Admin | Everything: Inventory, Roster, Staff, plus all the desk pages |
| `staff1` | Staff | Checkout, Return, Overdue, Event log |
| `zquin001` | Student | My loans |

The other students (`mrive002`, `jchen003`, ...) have no password until they activate. Go to
http://127.0.0.1:8000/accounts/activate/ (also linked from the sign-in page), type the username and that student's
activation code (printed in the terminal by `seed_demo`), then choose a password. To switch users, click **Sign out**
at the top right, or use the private window.

If sign-in fails, check that you ran `seed_demo` after the last `flush` (flush deletes every account), that
the server is still running at `127.0.0.1:8000`, and that the password is all lowercase.

**You need a code.** `seed_demo` printed an activation code for each student except `zquin001`. Copy
`mrive002`'s code from the terminal output. You can also use Luis's code from the US-02 demo.

1. In the private window, go to `/accounts/activate/` (or click the activation link on the sign-in page).
2. Enter `mrive002` with a **made-up code** and any password. You get a **generic error** that does not say whether
   the username or the code was wrong. *(AC 2)*
3. Enter `mrive002`, the real code, and the password `123`. The password is rejected as too short or too common, and
   the code still works. *(AC 1)*
4. Enter `mrive002`, the real code, and `demo-pass-123` twice. You are signed in and land on **My loans**, which shows
   CALC-001. *(AC 1)*
5. Click **Sign out**. The navbar shows **Sign in** again. *(AC 7)*
6. Go back to `/accounts/activate/` and reuse the same code. It shows the **same generic error**, because codes are
   single-use. *(AC 2)*
7. Click **Sign in** and enter `mrive002` / `demo-pass-123`. Sign-in works with only a local username and password. *(AC 4)*
8. Sign out and try `mrive002` with a wrong password, then `nobody99` with any password. Both show the **same
   message**, so it never reveals whether a username exists. *(AC 5)*
9. Deactivated account: run steps 1 and 2 of the US-02 demo (the spring roster), which deactivates `kjohn006`. Signing in or
   activating as `kjohn006` then shows the same generic error. *(AC 6)*
10. Stored password: in a second terminal tab, run
    `python manage.py shell -c "from django.contrib.auth.models import User; print(User.objects.get(username='mrive002').password)"`.
    It prints `pbkdf2_sha256$...`, a hash, never `demo-pass-123`. *(AC 3)*

**Tests:** `pytest inventory/tests/test_activation.py -v`

## Acceptance criteria and the tests that prove them

| # | Acceptance criterion | Test (`tests/test_activation.py`) |
| --- | --- | --- |
| 1 | A student activates with username and valid code, then picks a password | `test_activate_with_valid_code`, `test_weak_password_rejected_and_code_still_usable` |
| 2 | A wrong, used or expired code is rejected generically | `test_bad_code_rejected_generically` |
| 3 | The stored password is a hash | `test_password_stored_as_hash` |
| 4 | Sign-in uses a local username and password | `test_sign_in_is_local_username_and_password` |
| 5 | A wrong password does not reveal whether the username exists | `test_wrong_password_generic_error` |
| 6 | A deactivated account cannot sign in | `test_deactivated_account_cannot_sign_in` |
| 7 | A signed-in student can sign out | `test_signed_in_student_can_sign_out` |
