# US-06: Staff overdue list and in-app event log (8 points)

As a Staff member, I want a list of loans past their due time and an in-app event log, so that the
next shift can see what is late without email or a spreadsheet.

**Pages:** `/overdue/` and `/event-log/` (Staff and Admin).
**Code:** `inventory/views/overdue.py`, `LoanService.flag_overdue` and `overdue_loans` in
`inventory/services.py`, `LoanEvent` in `inventory/models.py`.

## What it does

- Opening the overdue list first flags newly late loans: one OVERDUE_FLAG event each, stamped with
  `overdue_flagged_at` so a refresh adds no duplicates (D-08). No scheduler needed.
- Days overdue counts a part day as a whole day (3 hours late = 1 day).
- The event log shows time, event, asset tag, the Staff member who acted, and any note. It never shows the
  borrower: borrower and item appear together only on checkout, return and overdue (Section 2.5).

## Demo, step by step

**Before you start** (see `docs/SETUP.md` for first-time setup). Make sure Postgres is running, then reset the demo data:

```bash
cd equipment-checkout
source .venv/bin/activate
export DB_PASSWORD=your-password
python manage.py flush --no-input
python manage.py seed_demo
python manage.py runserver
```

Open http://127.0.0.1:8000/. Every demo login uses the password `demo-pass-123`. Use a normal window and a
private window to be signed in as two people at once.

**How to sign in.** Click **Sign in** at the top right of any page, or go to http://127.0.0.1:8000/accounts/login/.
After `seed_demo`, these three logins work straight away (password `demo-pass-123` for all):

| Username | Role | What they see |
| --- | --- | --- |
| `admin1` | Admin | Everything: Inventory, Roster, Staff, plus all the desk pages |
| `staff1` | Staff | Checkout, Return, Overdue, Event log |
| `zquin001` | Student | My loans |

The other students (`mrive002`, `jchen003`, ...) have no password until they activate. Go to
http://127.0.0.1:8000/accounts/activate/ (also linked from the sign-in page), type the username and that student's
activation code (printed in the terminal by `seed_demo`), then choose a password. To switch users, click **Sign out**
at the top right, or use the private window.

If sign-in fails, check that you ran `seed_demo` after the last `flush` (flush deletes every account), that
the server is still running at `127.0.0.1:8000`, and that the password is all lowercase.

**Seeded state:** LAP-001 was checked out 80 hours ago with a 4-hour policy, so it is overdue.

1. Sign in as `zquin001` and go to `/overdue/`, then `/event-log/`. Both return **403**. Sign out. *(AC 1)*
2. Sign in as `staff1` and click **Overdue**. LAP-001 is listed with type, account `jchen003`, name, mock Panther ID,
   email, phone, due time, and **days overdue** (part days round up). CHG-002 and CALC-001 are not due yet, so they are not
   listed. *(AC 2)*
3. Click **Event log**. At the top is one **Overdue** row for LAP-001, created when you opened the overdue list. *(AC 3)*
4. Go back to **Overdue**, refresh it a few times, then return to **Event log**. There is still only **one** Overdue row
   for LAP-001: each loan is flagged once. *(AC 3)*
5. Click **Checkout** and lend `CHG-001` to `zquin001`. Then click **Return**, return `CHG-001` with **Damaged**
   ticked and the note `bent pin`, and open **Event log**. New **Checkout**, **Return** and **Damaged, moved to Repair**
   rows have appeared. *(AC 3)*
6. Look at the log's columns: time, event, asset tag, staff member, note. **No borrower name or Panther ID
   appears anywhere** in the log, so it cannot be used as a report of who borrowed which kind of device. *(AC 4)*

**Tests:** `pytest inventory/tests/test_overdue.py -v`
